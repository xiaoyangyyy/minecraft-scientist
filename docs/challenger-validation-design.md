# Public validation challengers: development experiment contract

Date: 2026-10-09. Status: implementation and verification in progress. This is
a prospective **validation-policy ablation**, not the complete research result.
The full objective remains H1/H2/H3/H4, formal structural holdouts and strong
baselines, unknown control/noise, controlled Minecraft, natural RGB exploration,
recovery and an integrated release.

## Question

Can a validator using only public history find counterexamples that an equally
funded coverage validator misses, without disproportionately losing correct
revisions or increasing unresolved cases?

The preceding generated-structure development probe exposed three incorrect
promotions for each structural method. An evaluator-only diagnostic found
affordable counterexamples. It had private after-truth and is **not** a feasible
Agent policy. Neither those counterexample actions nor case identities are
inputs to this new planner.

## Paired intervention

The source is a manifest-pinned completed development campaign. It selects all
members of its registered complete development groups and all four methods,
not just previously incorrect promotions. The loader validates every public
config/result before opening any selected private fixture content. It never
opens the source audit/report to select outcomes and never opens tuning or
evaluation fixtures.

Each pair inherits an identical public learning prefix:

1. Paid old learning and bootstrap.
2. Monitoring and anomaly detection.
3. New-epoch discovery and a frozen executable candidate, if available.
4. The unchanged eight random Wp validation queries, if reached.

Each branch **actually replays and pays for every reset and action** in that
prefix in a fresh world. Global episode clocks and hidden mutation schedules
remain intact. The final three validation slots alone differ:

| Branch | Final policy | Permitted knowledge |
|---|---|---|
| `public_coverage` | Existing seeded fresh coverage policy | Frozen candidate, paid prefix, public costs |
| `public_mutation` | Public behavioral mutation challengers | Same, including publicly acquired discovery/Wp evidence |

The inherited discovery plans are not regenerated, and original search compute
is not re-executed. Therefore this is not a new end-to-end learner comparison.
Actual prefix/tail costs and mutation operations are reported; timing covers
real replay and tail computation, not the inherited original discovery search.

Ineligible prefixes, no anomalies, missing candidates, prior counterexamples,
control/measurement failures and compute exhaustion remain in the denominator.
Known failures cannot reject a candidate. A valid prospective counterexample
rejects the proposed child and leaves the parent challenged. All required fresh
validation queries must succeed before the child is accepted and its parent
superseded. Confidence zero is not a calibrated posterior.

## Declared baseline and fault domain

The public mutation baseline enumerates the complete declared domain of **one
existing transition-row target or output replacement**. It does not insert
states, guarantee unknown-controller identification or cover arbitrary DSL
programs. A domain larger than the registered mutant limit is unresolved,
rather than silently truncated and called complete.

Deterministic full-behavior partition refinement deduplicates mutants. Public
evidence eliminates incompatible classes. A cost-ordered product search finds
minimum-cost unused candidate/challenger distinguishing words within the
registered horizon. An exclusion trie prevents incorrect pruning when a
cheaper path has already been observed. Selection greedily covers remaining
behavior classes per paid reset/action cost, with explicit fresh fillers when
fewer than three useful queries remain. The whole batch is frozen before any
tail dispatch; a partial or over-budget plan cannot promote a candidate.

Operations meter model lookups, mutant enumeration and search expansions. It
is a disclosed abstract compute measure, not a hardware-independent proof that
all algorithms spend equal CPU time. Wall/CPU timing is also retained.

Mutation-based test derivation is established related work:
[Aichernig and Jöbstl, MBT 2012](https://arxiv.org/abs/1202.6123).
Fault-domain completeness is an established concern in finite-state
conformance testing:
[Vaandrager and Melse, CONCUR 2025](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.CONCUR.2025.34).
This baseline is not claimed as a reproduction of either full algorithm, nor
as an original discovery method. A contribution would require a demonstrable
advantage beyond these methods under clearly matched assumptions.

## Verification and interpretation

The public verifier replays policy execution from typed public receipts and
checks fees, prefix identity, fresh-query predictions, failure semantics and
theory lineage. This shares the policy implementation and is an implementation
replay check, not a second independent algorithm implementation.

Separate evaluator-only raw compound tables audit recorded behavior and compare
the proposed/promoted program on bounded reset interventions. They do not call
the IR interpreter and do not return private counterexamples to the Agent.
Planner tests additionally compare search with independent exhaustive word
enumeration. Manifest/file coverage and report denominators are checked, with
semantic tamper-negative tests even after artifacts have been rehashed.

The analysis must report retained correct promotions, residual wrong promotions,
rejected wrong candidates, rejected candidates correct within the evaluation
horizon, unresolved cases, experiment costs and computational costs together.
An H-bounded correct candidate is not necessarily globally correct; a rejection
beyond that scope must not be hidden. A development group is the independent
unit, not its random renamings or repeat runs. These data cannot establish
statistical superiority, sealed structural generalization, H4 or Minecraft/RGB
completion.

If residual errors remain, investigate candidate-language/fault-domain coverage
and validation allocation on development only. Do not inject private diagnostic
witnesses, tune on the sealed splits, or relabel finite validation as proof of
unique causal mechanism identification.
