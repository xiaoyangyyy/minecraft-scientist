# H3 在线结构修订开发纵切面

这是开发实现与受限证据，不是整个 H3、方法创新、结构泛化或 Minecraft/RGB
验收完成。完整目标继续见 `research-framework-v2.md` 和 `quality-roadmap.md`。

## 从 H2 向前推进的实际差别

H2 给定参考机制并从九个固定联合候选中诊断。本实现先通过公开交互识别旧
机制，再取得新的验证实验，随后世界在未告知 Agent 的 episode 边界真实改变。
Agent 的入口只包含 capability view、公开 bootstrap 候选、动作成本、常规
序列及协议预算；不包含世界 seed、case、变化边界或变化后的程序。

第一次符合命令执行契约的预测反例使旧联合理论进入 challenged，不立即宣布
物理机制变化。候选同时包含旧机制/控制器故障及新机制/控制器解释。已知控制
失败不作为世界理论反例；底层回执仍明确只确认 issued command，实际送达未知。

## 受限语法、搜索和可识别性

沿用 total-mealy-v1 / TheoryIR。允许单行目标重定向、单行输出改变，以及复制
已有状态并重定位其自环、用一条重定向接入新状态。插入宏算两个编辑。
四状态开发父程序完整枚举 129 个机制程序，与三个已知控制器组合为 387 个
联合解释。生成器只接收旧公开 IR 和搜索协议，不接收世界或私有变化标签。

搜索预算默认 1,000，规划容量 512，不静默截断；不足时返回
search_budget_exhausted / planning_capacity_exceeded / unresolved。名称不决定
机制匹配；真实插入状态与生成状态使用不同名称，评分按行为而非字符串相等。

查询时域 H=5，使用精确有限深度状态划分管理 reset 行为等价类。这不是全局
等价或唯一因果恢复。已晋升 IR 明确限定 reset-only 和 intervention_horizon，
共享解释器拒绝越界执行。归因投影保留全部幸存候选；MDL 或编辑少仅用于
挑选代表，不把代表当作唯一真实结构。

## 旧理论与新版本的独立实验验证

旧版本从 bootstrap 证据形成后，先冻结三个新查询的完整批次与全部预测，再
执行。新版本在修订发现结束后同样取得新的验证批次。所有已执行发现查询
都从验证候选中排除，query ID 全局不复用，验证结果不拟合该候选。
协议优先覆盖候选预测的非静默结果，然后覆盖公开动作；这是候选相关的覆盖
验证，不宣称无偏随机留出或统计置信界。

整批验证先检查可支付性；不足不发出部分实验后错误晋升。失败终止本批次，
不沿用失败结果把同一候选重新标成通过。所有 bootstrap、验证、监控、复位、
等待、诊断和修订实验进入同一个总预算 240。验证支出还从发现预算中预留。
监控预算耗尽明确报告未解决，不伪装为已完成无变化监控。

成功事件顺序为旧 proposed/provisional/accepted/challenged，新
proposed/provisional/accepted，旧 superseded。注册表深快照保持旧 IR 内容，
父版本和反例保留。理论 confidence=0 是未校准占位，不把有限验证冒充概率
校准；晋升的证据是单独保存的冻结验证计划与执行记录。

## 独立审计

公开阶段完整重放整个 Agent 的执行顺序、候选、冻结批次、预算及版本记录。
另一个原始表编辑器重建每个生成程序，独立因子运行时核对联合编译、预测、
异常过滤与候选更新，独立加总所有实际成本；之后才允许打开私有规则。
共享生成器或编译器被注入一致错误时，即使 Agent 与策略重放同错，独立编辑/
因子检查也必须拒绝，并且不读取私有文件。

私有阶段逐 episode 使用真实边界前/后的原始组件执行全部控制轨迹；通过
独立有界乘积遍历验证 accepted 程序在全部允许 reset 查询至 H 的行为。
检测、机制归因、行为恢复和验证晋升分别评分，不把其中一个替代其他能力。

## 首轮 Windows 结果

两个旧模板 × 七种变化/负例 × 两种同预算规划器，共 28 次开发运行，全部
独立审计通过。seed 同时改变名称并按奇偶选择两个固定旧模板，不是独立
结构留出或两份统计泛化证据。

| 条件（每规划器） | 见证覆盖 | 多步熵/成本 IG |
|---|---|---|
| 四类结构变化、两模板 | 8/8 新版本在 H 内预测正确 | 8/8，实验成本与见证法相同 |
| 控制器故障、两模板 | 1 完成联合行为修订，1 未解决 | 2 完成联合行为修订 |
| 无变化、两模板 | 2 无异常，不生成替换 | 相同 |
| 超出编辑语法、两模板 | 2 model_mismatch，不生成替换 | 相同 |
| 错误宣布机制变化 | 0 | 0 |

控制故障成功修订的联合程序仍有机制归因歧义，并未唯一确定物理机制未变。
seed 0 控制故障的见证法花费 188 后仍未解决；IG 花费 195 完成 H 内联合行为
修订且保持归因歧义。seed 1 两法均花费 194。这是强基线优于见证法覆盖的
反例，必须保留；不能称完整诊断胜利或新方法优势。

四类结构变化分别是启动边重定向、WAIT 边重定向、产物状态保留、状态插入。
两模板的总成本分别为 112、112、68、95/94；首次监控反例均位于真实变化
episode，检测延迟 0。固定边界与监控安排使这些结果较容易，不外推未知
时间分布或噪声条件。验证正确的是 H 内行为，不一定是私有潜状态结构。

包含 127 个 Python 包文件；全部与当前源码及三个基准注册表按字节匹配。

逐文件摘要完全相同，三轮不是额外的独立科学样本。

的全量结果。

## 运行

```powershell
uv run minecraft-scientist benchmark-revision --output runs/<new-directory> --seed 0 --seeds 2 --budget 240
uv run pytest tests/unit/test_structural_revision.py tests/unit/test_revision_audit.py
```

输出必须是新目录，保存 registration、逐案例 config/bootstrap/run/events/
theories/audit、Evaluator 私有规则、report 与逐文件 manifest。源在运行前冻结，
运行后再次核对；产物使用固定 UTF-8/LF，无生成时间戳或绝对输出路径。
`configs/revision-development-v1.json` 是开发协议，不冒充正式统计预注册。

## 下一研究缺口

下一步需要独立结构/编辑组合留出、从头结构学习及真实可执行的自适应模型
学习强基线、完整推理成本、随机/未知控制器和噪声停止规则。当前仅两种
匹配时域规划器，不是完整方法矩阵。H4 的学习符号迁移与负迁移、受控
Minecraft、自然 RGB、自主导航、长程恢复、公平 LLM 比较及全量发布继续
按原目标验收，不因本开发纵切面通过而关闭。整体目标保持 active。
