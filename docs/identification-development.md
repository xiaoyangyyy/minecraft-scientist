# H1 首个实现：可执行机制区分的确定性基础

这是 `research-framework-v2.md` 的第一个可运行切片，不是完整科学家、开放结构
发现或创新结论。实现沿用共享 TheoryIR、TheoryInterpreter、AgentWorldView、
InterventionSpec、TransitionRecord 和 TheoryRegistry，未复制另一套理论系统。

## 当前能执行什么

受限 `total-mealy-v1` 语言表示完整确定性有限状态机制，最多 16 个状态、8 个
动作、128 个转移。解释器无 eval/文件/网络入口，检查全转移覆盖与标签引用。
同一程序可以通过共享 TheoryInterpreter 执行，世界侧与评测侧用独立的原始
转移表重放，不调用该执行函数生成真实结果。

规划器接收公开候选 IR、动作成本、常规证据和能力接口，不接收真值程序或
世界 seed。世界 seed 决定命名和开发实例；所有方法使用单独固定的策略随机种子。
这是可信 Agent 的能力边界，不是对恶意 Python 反射的安全沙箱。后续进程隔离
仍是更强安全要求，不能把不可 pickle 等检查当作完整隔离证明。

语法不同但所有可执行行为相同的候选进入同一行为类，不会因为克隆了更多
语法版本而放大先验熵。独立产品状态遍历检查等价；带正权成本的产品状态
搜索产生最小区分见证。有限时域内未找到见证不等于全局等价。

这些是已有自动机方法的工程基础，不是原创性声明。
[L# / Apartness（2022 修订版）](https://arxiv.org/abs/2107.05419) 已研究主动
自动机学习及自适应区分序列；新版方法必须进一步证明故障分离和结构修订
的增量价值，而不能以实现了区分序列就宣布创新。

## 实验契约

`configs/identification-development-v1.json` 在开发运行前记录设计。Agent 必须
在实际复位和动作之前写出计划及每个候选的完整预测。复位成本 1，每个动作
成本 1，常规初始轨迹成本 6；这些都计入总预算 20。最大查询时域为 5。

校准、实际步骤、失败和候选更新分开记录。已知不合规的执行会停止并计入
支出，但不淘汰环境理论。该规则的注入测试不是隐藏故障诊断成功的证明。
最后的行为类仅进入 provisional，置信度未包装成已经独立验证的确定性。
算法不声明唯一因果结构，尚无 shadow validation 晋升到 accepted。

独立审计先完整重放公开策略、预测、预算、动作和理论事件。任何重放不一致
都会在私有真值读取之前拒绝。通过后，才核对实际动作结果与私有原始表，
并枚举所有 1,364 个允许查询生成小规模最小成本证书和行为评分。
未解决/未提交理论的预测准确率是 null，不把第一个竞争候选的预测冒充结论。

## 五类开发模板

| 模板 | 常规证据 | 要测试的边界 |
|---|---|---|
| activation | 装载、启动、两次 WAIT、取出均成功 | 启动是必要条件，还是无因果作用的常规动作 |
| delay | 同样的常规轨迹 | 一次 WAIT 与两次 WAIT 的隐藏阈值 |
| toggle | 同样的常规轨迹 | 再次启动是否撤销已有状态 |
| equivalent | 两个语法/状态名不同、行为完全相同的程序 | 保留等价候选，不宣称唯一结构 |
| model_mismatch | 真实机制超出提供的候选 | 报告失配，不强行选择一个候选 |

每类 30 组 opaque 命名实例，六种方法共 900 次运行。这是固定模板的开发
协议验证；它不是 30 个独立结构，不是最终结构留出或跨机制泛化。

六种方法为合法查询随机、informative-random、单步 IG、多步熵/成本 IG、
最小见证覆盖和最优参考。主比较是同候选、同先验、同预算、同查询时域的
多步 IG。单步 IG 只是时域消融。最优参考是相同先验下的最小期望成本决策树，
不提前知道实际真值，也不声称是给定预算下的最优成功率策略。

## 目前结果与下一步决策

初始 Windows 两次各 900 运行的独立审计全部通过，5,402 个产物摘要逐一相同。
两轮源码保存在 `runs/h1-pre-format-source-v1` wheel，118 个 Python 文件与注册
源码逐个匹配。后来仅对 CLI 导入格式做调整，第三轮结果保留；其源码另存在
`runs/h1-import-format-source-v1`，不把早期产物改写为后续源码的证据。

正式跨平台复测之前固定了输出的 UTF-8/LF，避免平台默认换行破坏字节回放。
该冻结源码 Windows/Linux 聚焦回归各通过 67 项且用例集合一致。最终格式的
Windows v4/v5 与 Linux v1 各 900 次运行审计全部通过，每轮 5,402 个产物
逐文件验证且三轮字节摘要完全相同。118 个注册 Python 源文件与 wheel 快照
逐个匹配，核对进程 15025 退出 0。证据为
`runs/h1-fixed-lf-cross-platform-verification-v1.json`；后续源码修改不借用该冻结
阶段的回归结果。
这些是新测试加相关解释器/CLI 兼容测试，不是全量项目回归。

初始结果中，三个可区分模板的见证覆盖、多步 IG 与最优参考均是 30/30，
而平均总成本完全相同：

| 模板 | 最小新查询成本（含复位） | 见证覆盖总成本 | 多步 IG 总成本 | 最优参考总成本 |
|---|---:|---:|---:|---:|
| activation | 4 | 10 | 10 | 10 |
| delay | 5 | 11 | 11 | 11 |
| toggle | 6 | 12 | 12 | 12 |

因此当前结果支持协议、受限行为识别和小例子最小性检查，不支持超过强多步
IG 的方法贡献。少量 prediction_cache_misses 也不是完整计算成本：产品状态
搜索与所有其他计算必须单独计入，不能据此宣称计算效率胜利。

下一研究动作是多候选/未见结构组合、执行故障与机制变化的竞争解释、独立
影子验证和最小结构修订，再验证迁移。不得为了得到正结果削弱多步基线。

## 运行与产物

```powershell
uv run minecraft-scientist benchmark-identification --output runs/<new-directory> --seed 0 --seeds 30 --budget 20
uv run pytest tests/unit/test_mechanism_discrimination.py tests/unit/test_identification_audit.py
```

输出必须是新目录，不支持覆盖。注册记录先于运行写入，运行前后核对所有
118 个包源码哈希；结果与 manifest 固定换行且不包含时间戳。每个实例保存
config、candidates、events、run、audit，以及独立 evaluator 子目录下的私有真值。
最终报告包含全部 900 行及状态分布，保留随机方法的失败和未解决结果。
