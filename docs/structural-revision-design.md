# H3 结构修订：下一实现的契约与创新约束

状态：设计草案，尚未实现、未作为正式实验预注册。它在 H1/H2 已验证的开发
基础上提出下一实现要求，不替代完整研究框架或原 Minecraft/RGB 验收。

## 不可跳过的差别

当前 H2 在九个给定联合候选中归因，baseline 是给定参考，世界从 reset 起就
使用某个固定机制。下一阶段不能把选择其中一个候选命名为结构发现，也不能
把外部提供的 baseline 假装成本轮自主发现并验证的旧理论。

新的纵切面必须按顺序发生：公开交互学习旧机制、分开的实验验证旧版本、
机制或控制器在未告知 Agent 的边界改变、出现冻结预测的反例、诊断执行/机制
解释、在受限语法中生成新结构、独立验证新版本，最后保留完整替换事件历史。

## 结构语言与搜索边界

沿用 total-mealy-v1 和共享 TheoryIR，不另建特殊真值结构语言。公开提供编辑
语法，不提供改变后的转移表或真实编辑：

- redirect_transition：修改一个已有状态/动作行的目标；不改变其他行。
- change_output：修改一行公开输出；需要正负例防止只记忆一次异常。
- add_state_from_template：复制一个已有状态的行，原来的自环重定位到新状态，
  再通过明确的 redirect 将其接入；状态插入与重定向均计入描述长度及搜索。

首个真实变化至少覆盖旧机制固定参数族之外的转移边变化；随后增加状态数
变化与未见编辑组合。声明状态/动作、编辑长度、枚举量、保留候选与时间预算。
不能因为当前规划器容量有限就静默扔掉候选并宣称唯一识别。容量不足分别报告
search_exhausted、planning_capacity_exceeded 或 unresolved；有限语法内未找到
候选与“世界不存在可解释机制”是不同结论。

候选生成只使用 discovery 证据。每个生成程序保留父 IR、编辑序列、生成证据
和搜索计数；两个语法版本行为相同不应重复增加先验质量。编辑最少/MDL 最小
只是排名准则，不证明因果真值；所有未排除的行为或归因歧义仍需保留。

## H2/H3 的连接

真实命令送达仍是潜变量。旧机制 + 控制器变化应与生成的新机制 + 原控制器
竞争，必要时允许两者同时变化。诊断动作的执行、复位与观测成本进入同一
总预算。结构生成器不能读取控制器故障标签、世界 seed 或 Evaluator 输出。
候选覆盖不足时，不允许以“剩下的都是新机制”为充分的无条件归因证明。

一旦旧高置信预测失败，应记录异常，而不是立即 supersede 旧版本。进入
challenged 与决定机制改变、生成候选、验证通过、完成替换是不同事件；故障
解释得到支持时保留旧机制，修订控制器信念。噪声任务另需统计停止规则，不能
从确定性单个反例直接外推。

## 独立影子验证

前置缺陷：在 e05811e 的独立内存探针中，调用方修改传入 IR 或 get 返回值的
内部 parameters 字典，都改变了注册表保存的旧理论（0 → 1 → 2）。Pydantic
外层 frozen 不证明嵌套内容不可变；当前聚焦测试未覆盖这个不变性。证据为
`runs/h2-source-v1/registry-content-mutation-probe.json`。H3 晋升前必须实现注册表
自有的深快照与对外隔离快照，并测试输入、查询、历史和状态转换的嵌套别名。
当前全量回归使用原冻结源码，不在运行中改变其注册表实现。
随后注册表自有深快照修复已完成，七个输入/输出端口及版本/父版本边界测试
通过；新冻结阶段 Windows/Linux 各 169 项通过。详见
`registry-isolation-development.md`。它只关闭注册表内容隔离前置要求，未关闭 H3。

验证计划在执行前冻结，训练/生成证据 ID 与验证证据 ID 必须不相交。验证
轨迹不能用于同一候选的生成、选择或参数拟合；验证失败若反馈到生成器，
它成为下一轮 discovery 证据，下一候选必须取得新的验证预算和新实验。
独立 Evaluator 保持最终评分角色，不为候选提供免费真值反例。

晋升需要未见干预预测、声称作用域内的旧知识回归、候选歧义与执行不确定性
门槛。没有足够验证成本时停在 provisional。若只证明行为类，理论作用域及
报告均限定为行为，不强行标注唯一潜状态结构。注册表保留旧版内容、父子版本、
反例、验证事件与 supersede 理由，不回写历史轨迹。

## 强基线和创新边界

[Diagnosability Planning（AAAI 2017）](https://ojs.aaai.org/index.php/AAAI/article/view/10694)
已经基于给定正常/故障模型进行诊断动作规划；
[Adaptive L# / State Matching（FM 2024）](https://arxiv.org/abs/2406.19714)
已经利用参考模型结构改善主动模型学习。基础诊断、有限状态结构重学、参考
模型复用或加入版本注册表都不单独构成新贡献。

比较需要至少包括：同语法从头结构学习、适配后的旧模型复用/自适应学习、
同候选多步 IG、参数限定修订消融、忽略控制器不确定性的消融、完整方法。
比较纯规划时候选必须相同；比较端到端生成时语法、搜索/实验资源及提供的
参考知识必须相同。算法所需的成员/等价查询要映射到实际可执行实验或同预算
验证程序，不免费使用评测真值。若无法忠实适配，应明确标为受限近似，而不是
把一个弱实现冠以强基线名称。

待验证的增量问题是：在可信但可能未实现的干预下，联合诊断与结构修订能否
减少错误修订和总验证成本，同时不牺牲恢复速度、预测覆盖和迁移准确性？
这是研究假设，不是已经排除相关工作的原创性声明；更完整的综述仍需继续。

## 下一实现的验收证据

需要当前源码的测试、源/产物冻结与独立重放，也需要：未向 Agent 提供的真实
结构变化、带成本的独立验证、合法的旧 challenged/新 accepted/旧 superseded
事件、不应修订的控制故障负例、候选语法失配和预算不足负例、结构组合留出。
最终指标分别报告检测、诊断、结构恢复、验证晋升和总成本；只生成新程序或
训练样本拟合成功不算完成 H3。H4 与受控 Minecraft、自然 RGB 继续作为后续
完整目标保留，不因本设计或 H2 开发通过而关闭。
