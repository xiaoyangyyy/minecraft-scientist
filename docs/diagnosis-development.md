# H2 开发：把执行故障与机制改变作为竞争解释

本切片落实研究框架的执行/理论分离，不宣称 H2 全部完成或已证明创新。
在同一 TheoryIR 中组合机制程序与控制器程序，复用 H1 的规划、预算、预测
冻结、TransitionRecord 和理论注册表；没有另建一套 symbolic learner。

## 问题与可识别性边界

Agent 获得九个公开联合候选：三种机制 × 三种控制器。

- 机制：原机制、加工等待阈值改变、启动转移边被移除。
- 控制器：正常、主路径始终不送达启动命令、启动命令交替不送达。
- 普通初始操作：装载、启动、等待、取出。一次失败不能判断是哪种原因。

提供两个不同的动作契约：仅主路径，或额外提供成本更高的替代启动路径。
替代路径也是实验动作，不直接返回故障标签；其有效性是提供的控制器候选
共同假设，不是 Agent 自己发现的普适可靠性。

没有替代路径时，“原机制 + 主路径不送达”与“启动边移除 + 正常控制器”
可以在全部动作序列上行为等价。Agent 必须保留两个解释，不宣称唯一因果
归因。存在替代路径时，Agent 可以提出该路径上的实验并比较事先冻结的预测。

即使机制已经确定改变，控制器仍可能不可识别。例如启动本身完全无效时，
这条动作是否送达不影响结果。结果分别报告机制、控制器和联合行为的状态。
归因投影覆盖所有剩余候选，不使用排序最前的一个。联合行为未完全识别时，
如果所有剩余机制都排除原机制，仍可报告候选族内的机制改变；不能据此宣称
唯一机制结构或完成理论修订。

## 执行边界

World 原始运行时先执行隐藏控制器转移，再将实际送达的动作交给机制转移。
它不调用 JointHypothesis.compile 或共享 TheoryInterpreter 产生世界结果。
Agent 只得到能力接口、公开候选、成本、初始操作和原机制/原控制器参考 ID。
世界 seed、当前条件、真实送达动作、故障标志和私有组件不传给 Agent。

TransitionRecord 的 `intervention_compliance=True` 在本任务中只表示 issued-command
调度合规；context 明确标为 treatment_verification=unknown，并保留未验证执行
的混杂因素。不得把这个布尔字段解释为目标处理已经实际生效。观测仅有匿名
按钮及匿名结果信号，没有隐藏送达信息。Python 能力边界仍不是恶意反射沙箱。

## 预算和比较

设计在 `configs/diagnosis-development-v1.json` 登记。总预算 32，最大查询时域 5，
复位 1、普通动作 1、替代启动 3，初始操作也计入成本 5。复位明确同时复位
控制器隐藏状态；这不是自然环境中无法复位的持续故障。

见证覆盖与多步熵/成本 IG 得到相同候选、行为类先验、时域、成本和初始证据。
不以削弱信息增益基线获取胜利。九种真值组合、两种动作契约、两种规划方法
均保留逐实例结果；每个 world seed 产生 36 次运行。seed 只扰动固定模板的名称，
不是独立结构、正式留出或统计创新证据。prediction_cache_misses 不等于全部
推理成本，不能据此宣称计算效率优势。

## 独立审计

审计分两阶段：

1. 仅公开产物：完整重放策略、预算、预测和动作；独立检查编译程序与组件
   行为一致；通过原始组件重新过滤每次证据；检查归因投影没有虚假处理确认。
   任一不一致，禁止读取私有文件。
2. 冻结后读取私有组件：独立重放实际控制器和机制，核对完整公开执行结果；
   评分真实因子是否保留、机制/控制器改变是否正确、误报与未解决覆盖率。

Agent 的理论最多 provisional，尚无 shadow validation 或 replacement structure。
这里的 baseline 是外部提供的公开参考知识，不伪造本轮已经独立验证过的历史。

## 当前验证

第一批 Windows 聚焦回归 120 项通过，包含 63 项 H2 测试和 57 项 H1 测试。
首次批次的 pytest 参数迭代器弃用警告已修正；该报告保留，不覆盖。
修正后的当前源码 Windows/Linux 扩大兼容回归各通过 134 项，零失败、错误、
跳过，测试集合一致。Windows v1/v2、Linux v1 各 108 次开发运行的独立审计
全部通过，每轮 650 个产物逐文件核对且三轮字节完全一致。122 个包源码与
注册哈希及 wheel 快照匹配；完整进程回执与摘要为
`runs/h2-cross-platform-verification-v1.json`。冻结阶段复核命令为
`./scripts/verify_h2_development.ps1`；后续源码改变时应拒绝复用本证据。
这些不是项目全量回归，也不借用旧 H1 的 67 项或导航历史全量测试。

每种规划器在每种动作契约下包含 27 个开发案例（九种真值组合 × 三组名称）：

| 动作契约 | 机制状态判断正确 | 机制状态未解决 | 错误机制变化 | 平均总成本 |
|---|---:|---:|---:|---:|
| 仅主路径 | 9/27 | 18/27 | 0 | 15 |
| 主路径 + 替代路径 | 27/27 | 0/27 | 0 | 21 |

见证覆盖与多步 IG 的结果完全相同。这说明增加有效干预可以改变归因能力，
不是本方法超过信息增益的证据。替代路径条件中联合行为只识别 21/27，控制器
变化状态只确定 18/27；它们与机制状态判断分别报告，不隐藏局部未解决。
三轮平台回放不是三份独立科学样本，这 27 个名称案例也不是 27 个独立结构。

## 运行

```powershell
uv run minecraft-scientist benchmark-diagnosis --output runs/<new-directory> --seeds 3 --budget 32
uv run pytest tests/unit/test_fault_diagnosis.py tests/unit/test_mechanism_discrimination.py tests/unit/test_identification_audit.py
```

输出必须是新目录。运行前登记源码、成本和任务设计；运行后检查源未变化。
保存 config、hypotheses、run、events、audit、独立 evaluator 私有文件及逐文件摘要。

## 完整研究仍缺什么

H1 正式多结构留出与完整计算比较仍未闭合。H2 尚缺随机故障、观测噪声、
未知控制器结构及不可复位的状态信念；当前只是已知候选族的诊断。H3 尚缺
超出旧候选的结构生成、真实在线规则变化和独立影子验证晋升。H4 尚缺新研究
任务的学习库迁移和负迁移矩阵。公平 LLM 比较、受控 Minecraft、自然 RGB
闭环及原系统全量发布要求仍保留。当前结果不证明非常创新或整体完成。
