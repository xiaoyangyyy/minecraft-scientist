# Lossless expansion of structural development experiments

Date: 2026-10-09. This is an execution contract, not a claim that an expanded
campaign has already completed or that the complete research objective is met.

Revision 2026-10-10: the first all-development process terminated with
MemoryError after retaining 1400 six-file method runs, without a final manifest
or report. The complete 210-file source binding and 132 default tests were
byte-verified into `runs/compact-development-source-v1` before this revision.
Partial outputs are preserved, not certified or silently resumed as a success.

## Purpose and scientific invariants

The prior full development probe used one complete leakage group. Storage was
a practical barrier to extending it: the 64-run source campaign retains about
483 MB of JSON. A read-only gzip size probe estimated about 11 MB without
removing any data. Compression is an engineering enabler, not a method
contribution or permission to weaken the benchmark.

The expansion reuses the four frozen learners (`from_scratch`, `adaptive`,
`structural_witness`, `structural_ig`), the common paid lifecycle, public-first
policy replay, independent raw behavior scoring and public-mutation validator.
It does not cache free scientific evidence, reduce budgets, drop candidates,
remove failure trajectories, inject diagnostic counterexamples or tune sealed
conditions. Each method still performs its real learning/execution independently.

The existing default protocol is unchanged: total budget 600, old budget 250,
reset horizon 5, eight random Wp samples, four monitoring batches of eight,
seed 20261008, search/reference operation limits 200000, three final validation
queries. The known mutation fault domain and limit 512 are unchanged as well.
Compression CPU/storage are not presented as learner improvements. Learning
and audit timing retain their original scopes; storage/orchestration time is
outside those timers and must not be called full scientific compute.

## Selection and proposed extent

The manifest-pinned constructed corpus has 27 development leakage groups and
448 development fixtures. The intended expanded structural campaign includes
ALL of them and all four methods: 1792 method runs. The follow-on paid
validation comparison would include 1792 pairs / 3584 branches, including every
no-anomaly, failed, wrong, budget-limited and ineligible prefix.

The compatibility run first selects the same complete first group as the
historical probe. Its 384 per-run payloads and reconstructed results must agree
exactly with the original raw-JSON campaigns. Registration/report wrappers
differ because source bindings and the explicit storage contract differ.
Only after compatibility/source/test gates should the full development run
start. The full-run totals above are targets until actual terminal outputs and
audits prove them; a partial directory is not a completed result.

No tuning/evaluation fixture is opened. Selection is by registered complete
groups, never old audit outcomes. The independent unit is the leakage group;
renamings and repeats are not new samples. This is development, not formal
holdout/generalization or statistical confirmation. Sample design, strong
random/LLM/adaptive baseline fidelity and formal analysis remain open.

## Storage and verification contract

Each logical artifact is canonical UTF-8 JSON with sorted keys, two-space
indentation, one LF terminator and no NaN/Infinity. Every event, candidate,
theory version and private evaluator fixture is retained unchanged. Gzip uses
level 6, empty filename and mtime zero; the manifest stores compressed byte
hash/length and decompressed canonical payload hash/length separately.

The reader rejects unsafe paths, Windows device aliases, duplicate or extra
artifacts, malformed metadata, changed hashes, noncanonical JSON and bounded
decompression violations. A storage-bound failure retains partial evidence and
does not truncate it into a passing run. Existing output directories and files
are never overwritten. The final manifest is written only after complete source
and input checks. Timing is explicitly nondeterministic.

Logical payload hashes define scientific cross-platform identity. Different
zlib runtime versions can produce different compressed bytes; such a difference
must not be mislabeled different events or hidden by ignoring payload changes.
Physical stored-byte hashes are nevertheless always checked for corruption.

The revised writer incrementally encodes exactly the same canonical JSON and
feeds at most 64 KiB per gzip write, hashing/counting both layers without joining
whole-document buffers. An escaped individual JSON scalar may still be allocated
by Python's encoder; the input object and bounded reader's decoded object are
not memory-free. Readback compares canonical chunks without another full joined
encoding. A failed serialization/write permanently prevents that Writer from
certifying a manifest, retaining both prior complete files and partial bytes.

RecordedEpoch caches its AgentWorldView weakly. The separate capability registry
still owns callbacks strongly so a live view keeps its recorder/world usable;
the recorder no longer strongly retains the registry key. Completed experiments
can therefore release worlds and receipt histories. Global/local clocks,
receipt contents, public capability slots and learner algorithms are unchanged.
This dependency change is newly source-bound and does not borrow old test passes.

Private compressed references are lazy: the existing audit API gets only a
pinned `read_text` capability and opens it after public validation. Full audits
stream all public configs/results/history/evidence first, then read selected
private content and raw-score every run. This keeps memory bounded without
making the private/public separation weaker.

The paid challenger adapter freezes public prefixes before any selected truth
read. Each branch actually executes/pays every prefix reset/action and keeps
global episode clocks intact. Discovery plans and original search compute are
inherited, not regenerated; only final validation differs. Its report adds an
explicit public prefix-outcome category so bounded no-anomaly cases are not
mistaken for repair failures. This category never feeds the Agent planner.

## Evidence gates and interpretation

Before launch: frozen source dependencies, canonical/gzip/tamper-negative tests,
public-first I/O guards, legacy payload compatibility and paid-prefix lineage
checks. After launch: actual process terminal codes, exact file/method/group
coverage, source/input hashes, public policy replay, independent raw scores,
all outcome denominators and logical deterministic comparisons.

The intended analysis compares correct/wrong promotions, retained correct
revisions, additional counterexample rejections, unresolved coverage, actual
experiment costs and mutation compute together, by structure/group as well as
overall. Larger samples may contradict the first group's zero-error outcome.
Residual errors, blind fault domains and expensive/unresolved challengers must
be reported rather than filtered or addressed with private witness leakage.

H1/H2/H3/H4, unknown control/noise, symbol transfer and negative transfer,
controlled Minecraft, natural RGB/navigation, recovery and integrated release
remain the full project objective. This adapter does not complete or replace
any of those scientific or end-to-end requirements by itself.
