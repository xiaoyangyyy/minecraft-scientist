# 样本精度／功效设计工具：当前证据

日期：2026-10-10。契约见 [sample-design-contract.md](sample-design-contract.md)。
这是正式研究设计的前置算术工具，不是完整预注册或正式评测的通过证明。

## 实现

新隔离模块 `research/sample_design` 不读取世界、开发成绩、语料或封存条件，
也不修改运行中的 211 方法源及已有 219 分析源。输入要求精确 Fraction，
输出固定样本 IID Bernoulli 失败端点的最少采样单位数；同一泄漏组内重复、
重命名和重放不增加单位数，分组也不自动证明 IID。

除了零失败精度，支持非零失败容许数与给定良好错误率下的边际通过概率。
以精确整数二项尾概率决定方案／最小性；显示概率用向外舍入十进制包围，
不是浮点决策。有限资源耗尽明确报告或抛错，不缩小方案后称通过。多端点
采用预先声明家族下的 Bonferroni 分配，不声称全家族联合功效。

输出敏感性网格包含 1/5/10% 风险上限、1/4/8 个端点，以及零／一次失败
方案和 80% 边际功效方案。良好错误率示例为风险上限的四分之一。上述数值
均非项目验收阈值，不能在看过开发结果后把它们称为正式事前研究选择。

例如 5% 家族误差、5% 风险上限：零失败需要 59 单位（单端点）或 99 单位
（八端点）；在良好率 1.25%、80% 边际功效条件下，最少方案为 153 单位／
允许三次失败，或 242 单位／允许四次失败。这是条件算术，不证明方法效果。
假设 18 个 IID 单位且零失败，单端点上界约 15.33%，八端点约 24.57%；
这不是当前语料的实际推断，现有封存 18 组也不能被工具自动认定独立或足够。

## 验证

冻结七个代码／测试／说明／契约文件，记录于
`runs/sample-design-source-registration-v1.json`。Windows／Linux 聚焦各
84 项实际退出 0，零失败／错误／跳过且唯一 case 集相同。独立样本空间枚举
核验尾概率，另用组合多项式及 n/k 穷举核验最小性／功效；覆盖精确等号、
无方案、资源边界、非法输入、包围舍入和 CLI 重复。合成算术不算科学世界。

CLI 两平台实际退出 0，九行敏感性网格、六个假设零失败上界和七文件源绑定
报告一致；保存 JSON 与本版确定性生成字节相同。原 211／219 源对已完成
绑定逐项核验未变。首次 pytest 因 root bootstrap 缺失在收集阶段退出 1，
修复后 73 项仅是中间结果；随后扩充独立 oracle／边界并冻结的 84 项才是
当前证据。一次只读核验命令在 PowerShell 引号解析失败，修正后完整检查
退出 0；失败未覆盖为通过。

机器证据见 `runs/sample-design-focused-verification-v1.json`；敏感性产物为
`runs/sample-design-sensitivity-v1.json`，七源已逐字节归档。无需 API Key 或
新依赖。命令：`uv run python scripts/plan_sample_precision.py`。

## 仍开放的研究／系统门槛

仍需真正独立世界的采样／结构留出设计、固定组内协议、主要端点及科学风险
阈值、失败／无异常／未解决分母、覆盖约束、完整多重比较家族、配对方法
效果的功效／精度设计、完整费用与强基线冻结。本工具不关闭这些正式预注册
要求，也不关闭未知控制／噪声、H4／负迁移、受控 Minecraft、自然 RGB、
导航、长恢复和整合发布。全开发矩阵必须实际结束并审计后再进入全量配对。
