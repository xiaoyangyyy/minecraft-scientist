## 为什么不能只换 seed / opaque ID

同一可执行机器换对象名、潜状态名、动作名、输出名或转移表顺序，不应变成
独立测试结构。不同潜状态图还可能实现完全相同的 reset 行为。只按文本哈希
或世界名称分割，会把开发中见过的行为伪装成未见机制。

`research/structural_holdouts/identity.py` 直接检查原始总 Mealy 表，独立于
TheoryIR 编译器、学习器及私有评分函数，产生两种保留规范正文的身份：

- structure：可达根图的规范形式，保留状态和转移结构。
- behavior：先独立消去等价状态，再规范化；限定于有限确定性 reset 机器的
  全部有限动作词，不是噪声世界、连续运行或唯一物理因果结构的证明。

规范化保持动作成本颜色和可见 reset 输出锚点，去掉 opaque 名字与表顺序。
before/after 元组使用同一套动作/输出重命名，不能分别改名抹掉角色变化。
不可达状态保守忽略；同成本动作还要求其他公开契约/特征相同。当前明确
限制最多6动作、3输出、16状态、128行；更丰富动作不能直接套用此身份。
超出预先声明的排列预算时拒绝产生身份，不以部分搜索哈希冒充精确结果。

泄漏分组按调用方声明的 target/pair 等身份键做连通闭包。结构或行为碰撞及
其传递桥接必须留在同一组，再按冻结 salt 分配开发/调参/评测。组可能不
平衡，真实采样单位是组而不是重命名数量；增加桥接数据需重新冻结划分。
SHA-256 是索引，不是数学无碰撞保证，规范正文供独立相等检查保留。全部
身份和真实表属于基准构建/Evaluator，不能反馈 Agent 或实验选择。

这是一个组的兼容性/失败分析，不是留出学习器成绩；其他开发组尚需扩展，

   正式方法/统计冻结前不在评测分区调算法，也不悄悄换salt筛选有利划分。
2. 在完整先验/目标/组合泄漏策略下增加正式独立组与条件覆盖，另外补齐
   预算不足、已报告执行失败、未知控制与观测噪声；它们不是当前确定性表
   构建已经解决的问题。按效应量/精度设计真实样本量。
3. 冻结方法、采样单位、预算、统计分析与停止规则，之后才运行全部强基线

   不关闭未知控制/噪声、H4学习符号迁移、Minecraft/RGB与发布要求。
