# 同等公开先验与付费旧理论验证：开发阶段

日期：2026-10-09。目标是修复上一轮控制器组稀疏路径的旧模型覆盖缺口，并为
完整公平 H3 比较建立共同入口。不是完整强基线矩阵、结构留出、因果归因、
学习符号迁移、未知噪声、Minecraft/RGB 或研究创新验收。

## 当前实现

`shared_bootstrap.py` 只接受公开联合候选、校准序列、成本与声明预算，不接受
世界、私有边界或变化后程序。两个基线取得相同 9 个公开机制/控制器候选，
按相同 witness-cover 发现策略支付最多 40 成本；确定一个行为类后，再支付
未参与发现的 3 个 prospective shadow 实验，优先预测正产物和公开动作覆盖。
整个验证批次预先冻结，预算不足不部分执行后接受；失败不继续拟合此候选。
这是已知候选族识别，不是完全无先验的结构发明。

验证通过才发布旧理论并监测。新证据时代和修订学习器、随机 Wp 验证保持原
契约，adaptive 仅复用自己付费旧 IR，from_scratch 忽略该参考。两者的旧
发现、验证、监测、费用与剩余修订预算完全一致。实际送达仍未知，不将公开
联合行为正确宣布为物理机制/控制器唯一识别。新候选有限通过仍可能错误。

`audit_bootstrap.py` 在任何私有读取之前，以原始因子表独立检查候选编译、
H 内行为类、冻结预测、实际动作与费用、失败/完整证据、候选过滤，以及用
原始表重新计算整个覆盖计划；随后核对发现/验证分离、扁平账本与策略重放。
原有审计继续检查全局时钟、warning、监测、修订、版本谱系与私有门禁。
同策略重放不是所有共享缺陷的证明，另有编译与覆盖共享故障注入测试。

## 证据阶段与边界

当前 14 个阶段文件由 `runs/shared-bootstrap-source-registration-v1.json`
冻结，20 个上游文件、主包 130 个 Python 源与 131 个默认测试均无哈希变化。
Windows/Linux 组合聚焦各 362 项通过，零失败、错误、跳过，两进程退出 0；
其中当前在线目录 127 项，上游 235 项。这不是默认全量或端到端验收。
同一主包冻结的 Linux 默认全量现已实际退出 0：1748 通过、2 项 Node.js
依赖跳过；XML 共 1750 项。它是独立主包证据，不是当前隔离目录的默认收集。
核验见 `runs/apartness-full-linux-verification-v2.json`，130 源/131 测试无变化。

首批 41 项与中间组合 354 项也通过，但它们早于最终新增负例及冻结，只是
中间证据。最终 362 项覆盖公开先验分离、付费/整个批次可支付性、正产物和
动作覆盖、独立证据、未告知早晚变化、已知失败、双方法一致入口、字母表
消融、布尔费用/行为类篡改、共享编译与覆盖错误，以及任一私有读取前门禁。

历史 11 文件阶段已逐字节归档 `runs/online-automata-source-v1`。历史验证器
`verify_online_automata_development.ps1` 只用该归档核对旧 313 项/650 文件证据，
上游 20 文件及主包冻结仍独立核对。当前新增代码不由历史通过结果认证。

默认 runner 控制器组用 `--bootstrap-mode known-family`，原 `alphabet` 模式
作为明确的知识条件消融保留；两动作组始终只有字母表。知识条件不混成纯
算法优势。完整 H3 尚未接入这一入口，故当前仍不与其作完整公平优势比较。

## 开发网格结果与仍存在的失败

两 seed、54 对/108 次，预算 600、旧预算上限 250、H=5；保持原四类两动作
任务的边界 0/8/16/24/1000，七类控制器任务边界 25。新先验仅用于控制器组，
这是明确改变知识条件/验证政策的实验，不把相对历史字母表组的改善称作纯
学习算法或独立结构泛化收益。

| 全部 54 次，每种方法 | from_scratch | adaptive |
|---|---:|---:|
| 有限验证后的替换 | 21 | 18 |
| H 内正确的新模型 | 16 | 16 |
| 有限通过但错误的新模型 | 5 | 2 |
| 未解决 | 6 | 9 |
| 有界监测内无异常 | 27 | 27 |
| 真实边界后行为异常 | 21 | 21 |
| 无 H 内变化或边界前的异常 | 0 | 0 |

双方修订正确的 16 对全部是 from_scratch 更便宜，adaptive 无成本胜出。
这是修订模型正确条件下的比较，不是因果成功或统计显著优势；错误/未解决
仍在整体分母中。不能把 adaptive 少 3 个错误而多 3 个未解决称作已经证明
校准、稳定收益或因果归因能力。

控制器组每方法 14 个旧理论全部在 H 内正确，原字母表阶段的稀疏路径缺口
在这一已知先验条件下被修复。每法检测 9/12 个 H 内真实变化，另 3 个变化
（seed0 控制器故障与两个 retain_ready）未被有界随机监测发现；2 个无变化
正常完成监测。from_scratch 修订 4 正确、5 错误，adaptive 4 正确、2 错误、
3 未解决。状态插入的两例新模型仍都错误，说明旧模型修复不等于结构修订
成功。未检测、错误 accepted 和语法外实例保留完整原始证据。

全表 `wrong_old_models_at_H=6` 均为两动作边界 0 的交互前切换实例，它们学习
的是 after 而非 before，不代表控制器旧模型仍有 6 个拟合错误。无异常也
只表示限定窗口未见反例；尤其不能宣称真实变化不存在或长期误报率为零。

Windows 两轮和 Linux 一轮均完成，650 个确定性文件逐字节一致；每轮另有
manifest 与 timing（共 652 文件）。报告/源/产物冻结记录见
