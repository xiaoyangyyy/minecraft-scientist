# Public validation challengers

Development-only public-model mutation baseline and paid paired validation
ablation. This is not an originality claim or a complete scientific learner.
The full contract is in `docs/challenger-validation-design.md`.

The planner accepts only a frozen public candidate, public action costs,
previous words and publicly observed evidence. It enumerates a declared single
row target/output fault domain, deduplicates full behavior classes, filters
publicly refuted explanations, then freezes three paid fresh experiments.
It does not access evaluator tables or private diagnostic witnesses.

The paired adapter re-executes and pays every inherited old-learning,
monitoring, discovery and eight random-Wp validation action. Only the last
three coverage/challenger slots differ. Original discovery plans/compute are
inherited, not regenerated. No-candidate and ineligible prefixes are retained.
Global episode clocks remain intact; local learner clocks are reversibly
rebased. All complete registered development groups and four source methods
are included; the source score/report is not used to select cases.

Public receipt replay checks chronological execution, frozen policy decisions,
fees, fresh evidence and theory lineage. Independent evaluator raw tables score
bounded issued-command behavior only after public verification. No finite
validation pass certifies all-H behavior or unique physical causal factors.
The test suite also checks independent exhaustive minimum-cost word references,
opaque renaming, failure semantics and semantic tamper-negative cases.

```powershell
uv run pytest research/challenger_validation
uv run python scripts/run_challenger_validation_development.py --source <pinned-source-campaign> --source-manifest-sha256 <certified-sha256> --corpus <pinned-development-corpus> --corpus-manifest-sha256 <certified-sha256> --output <new-directory>
```

Repeat the runner command with `--verify-only` to validate a completed output.
Never use tuning/evaluation splits as inputs. Mutant limits, compute limits,
control/measurement failures, wrong promotions, rejected candidates and
unresolved cases must be reported rather than filtered away. One development
leakage group is not sixteen independent worlds. Strong baseline fidelity,
formal sample/holdout design, unknown control/noise, H4 and Minecraft/RGB remain
open requirements.
