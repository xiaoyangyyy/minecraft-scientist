# Paid online behavioral relearning prototype

Isolated research implementation, NOT accepted full H3/H4 or project completion.
It imports the frozen paid/from-scratch adaptive learner and existing TheoryIR.
No main package/default test files or earlier prototype freezes are modified.

That paragraph describes the archived phase, not the current matched-H3 change:
the shared bootstrap/checker now live in `agent/bootstrap.py` and
`evaluation/bootstrap.py`; compatibility modules here alias them. The existing
H3 loop and this lifecycle use one `discover_structural_repair` core. Main H1
measurement failures are paid but no longer treated as mechanism evidence.
Previous 130/131 main source/test and 14-file bootstrap phases are byte archived;
their green counts cannot certify current code.

The new `run_matched_h3_development.py` compares four declared discovery methods
with the SAME paid prelude, monitoring and final random-Wp-plus-coverage protocol.
All actual discovery/internal-conformance/final-validation bills are charged.
Internal tests are discovery for this lifecycle, not its promotion evidence.
Valid final counterexamples retain rejected child versions; control/measurement
failures retain provisional children and never refute their mechanisms.
Structured methods use declared edit/controller priors; finite-state methods use
their general bounded Mealy language. This bias is disclosed, not called a pure
identical-candidate planning comparison. The checkout runner is not yet a packaged
four-method CLI or full release. See `docs/matched-h3-development.md`.

The same old learning policy and bounded Random-Wp monitoring are paid by both
methods. The world changes on an episode schedule withheld from the Agent. A
completed, compliant prediction counterexample challenges the old **issued
behavior** theory; known dispatch failures are paid/excluded and do not challenge
it. The repair learner starts a fresh evidence/cache epoch; adaptive receives
only its own paid public old IR, scratch deliberately ignores that reference.
Fresh final validation is disjoint from generation, then new accepted and old
superseded snapshots are recorded. Finite acceptance can still be wrong.

`RecordedEpoch` rebases only returned episode IDs. The original global clocks
and receipts are retained and independently checked, including reversible local
mapping, episode continuity and receipt uniqueness across learning/monitor/repair.
Monitoring uses a fresh per-query tree, not a stale membership cache. Entire
monitor batches are frozen/preflighted; early counterexamples/failures terminate
the batch with actual costs, not a fabricated complete validation pass.

`audit_online.py` first checks both learning phases, raw seeded monitor plans,
actual query ledgers, global clocks, paid priors/remaining budgets, registry
lineage and whole policy replay. Only afterwards may it read the private schedule
and score raw finite-table/factor behavior through H. It detaches inputs before
private callbacks. Same-learner replay and targeted independent checks are not a
proof against all shared defects.

The existing deterministic H3 controlled worlds explicitly retain their
`unverified-actuator-delivery` warning and issued-command/unknown treatment scope
in both raw/local receipts and replay. The inherited stationary raw checker is
used through an explicit *issued-behavior* projection for this one exact warning;
no physical-treatment verification or controller/mechanism attribution is
introduced. Other unmodeled warnings/noise are rejected, not silently removed.

Early changes may invalidate learning, pass a wrong old finite model, or cause an
anomaly before the nominal switch. Late changes may lie outside monitoring. These
are reported alongside wrong replacements and unresolved cases. No-anomaly means
only the bounded monitor window completed, not absence of a future/hidden change.
One bounded crisis is supported, not sustained arbitrary repeated nonstationarity.

```powershell
uv run pytest research/online_automata -q
uv run python scripts/run_online_automata_development.py --output runs/<new-directory>
```

The current default controlled condition uses the SAME declared public bootstrap
family/calibration for both methods, paid witness-cover identification, then
fresh positive-if-available/action-coverage shadow validation. `shared_bootstrap.py`
reuses production identification/validation, rather than treating evaluator
answers as old knowledge. `audit_bootstrap.py` independently checks raw factor
compilation, behavioral classes, frozen query predictions, filtering, cost,
complete prospective coverage, disjoint evidence and publication before private I/O.
An accepted old model can still be wrong outside the supplied family/finite scope.
`--bootstrap-mode alphabet` preserves the earlier no-family ablation explicitly.
Two-action tasks remain alphabet-only. The repair learners/tester are unchanged.

The development grid has two seeds, four two-action cases with five hidden
boundaries, and seven existing controlled H3 cases. Both baseline methods have
matching initial knowledge/tester/budget within each condition. Existing full H3
methods are NOT yet routed through this common entry or compared as matched here.
The shared bootstrap is an entry towards that comparison, not its completion. This is
not structural train/test holdout, statistical superiority, causal identification,
learned-symbol migration, unknown stochastic delivery, natural Minecraft/RGB,
recovery/release or a novelty claim. Source-bound runs/tests are separately recorded
in `docs/shared-bootstrap-development.md`. The previous 313-case/650-artifact
phase is byte-exact archived under `runs/online-automata-source-v1` and documented
in `docs/online-automata-development.md`; its verifier reads that historical source,
not this changed implementation. Old green counts cannot certify changes.
